3Create the conda environment

An environment is a private Python, so this class cannot break your other projects. No conda yet? Install Miniconda from docs.conda.io/en/latest/miniconda.html, then close and reopen your terminal. Run these two lines, one at a time:

conda create -n uu -c conda-forge python=3.12 numpy "pandas>=2.2,<3" matplotlib \
      seaborn scipy statsmodels networkx ipykernel jupyterlab
conda activate uu
  • It finished without an error (a few minutes), and my prompt now starts with (uu).

4Point VS Code at that environment

VS Code will not find it on its own, and this is the step people skip. Press Cmd/Ctrl + Shift + P, type Python: Select Interpreter, and pick the one labelled uu.

  • The status bar at the bottom of the VS Code window now shows uu.

5Fork the repository, then clone your fork

You work in your own copy, not mine. A fork is your own GitHub copy of my repository: you push your work to yours, and pull my updates from mine. One fresh repository per lab.

Fork it on the web first. At github.com/smgroves/UU_F26, click Fork (top right) and keep the name. You now own github.com/YOUR-USERNAME/UU_F26.

Option A · GitHub Desktop recommended

Install from desktop.github.com and sign in, which also settles your push permissions. Then File > Clone repository > GitHub.com, pick the UU_F26 under your own username, and set the local path to your class folder. If it asks how you plan to use the fork, choose the option about your own purposes, not contributing to the parent: that keeps your pushes going to your fork, not mine.

Option B · Command line

In VS Code's terminal (Terminal > New Terminal), from your class folder, with your own username:

git clone https://github.com/YOUR-USERNAME/UU_F26.git

Then everyone, in VS Code's terminal, add my copy as upstream and check both remotes:

cd UU_F26
git remote add upstream https://github.com/smgroves/UU_F26.git
git remote -v
  • origin shows my own username (where my work goes) and upstream shows smgroves (where updates come from).
  • UU_F26 is in the VS Code sidebar next to data, and contains Day_1_python_test.ipynb.

If it breaks

"conda: command not found": you did not reopen the terminal after installing Miniconda. On Windows, use the Anaconda Prompt rather than the default terminal.

The kernel picker does not offer uu: quit VS Code entirely and reopen. Still missing? You left ipykernel out of step 3: run conda install -n uu ipykernel.

No /uu/ in the interpreter line: the notebook is running a different Python than your packages went into. The most common problem in this class, and fixing it now beats fixing it Thursday. Redo step 4, then re-pick the kernel.

origin says smgroves: you cloned mine instead of your fork. Delete the folder and redo step 5 starting from the Fork button, or just repoint it: git remote set-url origin https://github.com/YOUR-USERNAME/UU_F26.git

"git: command not found": install GitHub Desktop, which includes git. On a new Mac you can instead run xcode-select --install and wait for it to finish.

The push is rejected, or asks for a password: GitHub stopped accepting passwords in 2021. Use GitHub Desktop, which handles this for you, or set up a personal access token or SSH key. Come find us rather than fighting it.

"No such file or directory: cville_cars.csv": the notebook has to run from inside UU_F26. Open it from the sidebar rather than moving the file.
